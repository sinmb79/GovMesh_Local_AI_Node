# User Requirements

## Repeated User Complaints

- 느리다.
- 왜 느린지 모르겠다.
- Windows 또는 WSL 환경에서 설치와 실행이 어렵다.
- GPU가 잡히지 않는다.
- 노드가 서로 못 찾는다.
- 백그라운드 작업이 CPU/RAM을 과도하게 사용한다.
- 로컬 서버가 외부에 노출될까 불안하다.
- 모델이 근거 없이 답한다.
- 개인정보가 로그에 남을까 걱정된다.
- 자동 에이전트가 업무 절차를 마음대로 바꿀까 불안하다.
- 한국어 행정 말투와 근거 인용이 약하다.

## Personas

### P1. 일반 공무원

- 문서 검색과 초안 작성이 빨라야 한다.
- 멈춘 것처럼 보이는 상태를 싫어한다.
- 개인정보와 내부문서가 외부로 나가지 않는다는 확신이 필요하다.

### P2. 부서 AI 담당자

- 설치, 성능 진단, 모델 추천, 장애 원인 확인이 쉬워야 한다.
- PC별 가능한 작업과 제한을 한눈에 봐야 한다.

### P3. 보안 담당자

- 모든 중요 작업에 감사로그가 있어야 한다.
- 외부 반입과 외부 전송은 정책 승인으로 통제되어야 한다.
- 원문 PII 로그 저장은 금지되어야 한다.

### P4. 기관 관리자/조달 담당자

- 어떤 PC 등급에서 어떤 기능이 가능한지 수치가 필요하다.
- 모델 라이선스와 운영 책임 경계가 명확해야 한다.

## Functional Requirements

| ID | 요구사항 |
|---|---|
| FR-001 | 노드 등록 |
| FR-002 | 노드 상태 보고 |
| FR-003 | 성능 진단과 추천 |
| FR-004 | 로컬 문서 스캔 |
| FR-005 | 개인정보와 민감정보 탐지 |
| FR-006 | 로컬 RAG |
| FR-007 | 근거 기반 답변 |
| FR-008 | 외부 연결 기본 차단 |
| FR-009 | append-only 감사 로그 |
| FR-010 | 정책 차단 설명 |
| FR-011 | 사용자 또는 관리자 승인 |
| FR-012 | 벤치마크 하네스 |

## Non-Functional Requirements

| 항목 | 요구사항 |
|---|---|
| 보안 | 외부 연결 기본 차단, PII 마스킹, 감사로그 |
| 성능 | 낮은 PC에서도 safe mode 동작 |
| 안정성 | 작업 실패 시 재시도와 우회 |
| 설명가능성 | 근거 문서와 정책 결정 이유 표시 |
| 사용성 | 초보자도 설치, 진단, 실행 가능 |
| 확장성 | runtime/model/provider 교체 가능 |
| 감사성 | 누가, 언제, 무엇을, 어떤 근거로 요청했는지 기록 |
| 운영성 | 노드 상태, 작업 대기열, 에러 로그 확인 가능 |
| 폐쇄망 대응 | 외부 네트워크 없이 테스트 가능 |
